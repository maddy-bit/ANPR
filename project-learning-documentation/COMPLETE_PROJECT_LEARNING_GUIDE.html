CHAPTER 02

Project Overview & Feature Inventory

The City AI Multi-Camera ANPR Trajectory Tracking & Urban Traffic Intelligence Platform was engineered to solve Bharat Electronics Limited (BEL) Problem Statement SIH26127 for the Smart India Hackathon.

1. The Operational Problem

Modern smart cities deploy hundreds of high-definition CCTV cameras across arterial intersections, expressways, and municipal junctions. However, law enforcement and municipal traffic management authorities face severe operational bottlenecks:

  • Siloed Video Feeds: Footage from individual cameras is rarely correlated in real time. Investigators must manually review terabytes of asynchronous video across dozens of junctions to trace a suspect vehicle's path.
  • Atmospheric & Environmental Degradation: Heavy haze, fog, rain, headlight glare, and dust severely reduce visibility, rendering traditional Optical Character Recognition (OCR) engines completely ineffective.
  • Plate Misreads, Cloning & Obscuration: License plates may be covered in dirt, physically damaged, or cloned onto a decoy vehicle. Relying solely on exact license plate strings leads to broken trajectories or false arrests.
  • Physical Impossibility & Ghost Sightings: Naive systems that connect detection timestamps without kinematic validation trust erroneous plate reads, displaying vehicles "teleporting" 15 kilometers across a city in 30 seconds.

CHAPTER 04

System Architecture & Subsystem Decomposition

The platform follows a distributed, multi-tier microservices architecture designed to decouple high-concurrency business transactions and relational state from heavy deep-learning computer vision tensor computation.

1. Architectural Principles

  • Language Isolation for Optimal Performance: Computer vision libraries (PyTorch, Ultralytics, EasyOCR, OpenCV) are Python-native. Conversely, enterprise transaction management, high-concurrency thread pooling, WebSocket connection tracking, and spatial database persistence are best served by the JVM (Java 21 / Spring Boot). Python handles vision; Java owns state and business logic.
  • Encapsulated Intelligence Tier: The Python AI microservice is not exposed directly to the public Internet or the browser. It operates strictly behind the Spring Boot application tier, which acts as a secure API gateway, authenticator, and rate limiter.
  • Dual-Profile Spatial Persistence: To ensure zero-friction local developer onboarding without requiring local PostgreSQL setup, the backend defaults to an in-memory/file-based H2 database. Setting SPRING_PROFILES_ACTIVE=postgres seamlessly activates real PostgreSQL 16 with PostGIS 3.4 spatial indexes and ST_DWithin geographic nearest-neighbor queries.
  • Fail-Open Resilient Distributed Caching: All caching, rate limiting, and Pub/Sub messaging are backed by Redis 7. Crucially, all Redis filters and caches implement fail-open exception handling: if Redis experiences a temporary outage, user requests fall through cleanly to the database rather than crashing.

Mathematical Theory: Atmospheric Scattering Model

In foggy or hazy conditions, light reaches the camera sensor through scattering: $$I(x) = J(x)t(x) + A(1 - t(x))$$ where $I(x)$ is the observed hazy image, $J(x)$ is the true haze-free scene radiance, $A$ is the global atmospheric light, and $t(x)$ is the medium transmission map ($t(x) = e^{-\beta d(x)}$).

Line-by-Line Code Walkthrough

  • get_dark_channel(image, patch_size=15) (Lines 17–22): 
    min_channel = np.min(image, axis=2)
kernel = cv2.getStructuringElement(cv2.MORPH_RECT, (patch_size, patch_size))
dark_channel = cv2.erode(min_channel, kernel)
return dark_channel
    Calculates the minimum pixel intensity across RGB channels, then applies morphological minimum filtering (erosion) over a $15\times15$ rectangular window. In non-sky regions, at least one color channel has very low intensity (near zero).
  • estimate_atmospheric_light(image, dark_channel) (Lines 25–36): Selects the top 0.1% brightest pixels in the dark channel (which correspond to the thickest fog/haze) and identifies the maximum RGB value among those pixels to establish atmospheric light vector $A$.
  • estimate_transmission(image, A, omega=0.85) (Lines 39–43): 
    norm_img = image.astype(np.float64) / np.maximum(A, 1.0)
transmission = 1.0 - omega * get_dark_channel(norm_img, patch_size)
return np.clip(transmission, 0.1, 1.0)
    Estimates transmission $t(x)$. A lower bound of $0.1$ is enforced to prevent division-by-zero artifacts in dense fog. Parameter $\omega = 0.85$ preserves a natural sense of aerial perspective.
  • ImageDehazer.dehaze(image_bgr) (Lines 46–95): Reconstructs true scene radiance: $$J(x) = \frac{I(x) - A}{\max(t(x), t_0)} + A$$ Applies a $15\times15$ Gaussian blur to smooth the transmission map and eliminate halo edge artifacts. If try_clahe=True, converts to LAB color space, applies Contrast Limited Adaptive Histogram Equalization (CLAHE) on the L-channel (clip limit 3.0, grid $8\times8$), and converts back to BGR.

How ByteTrack Works Internally

Standard tracking algorithms discard low-confidence detections ($<0.6$), losing tracked targets during temporary occlusion or motion blur. ByteTrack retains both high-confidence and low-confidence detections. Character Confusion Mapping & Indian Plate Regex

CCTV cameras capturing fast-moving vehicles suffer from pixelation and angle skew. OCR engines frequently confuse visually similar alphanumeric glyphs. ocr.py implements a domain-specific character substitution dictionary and regex validator:

    r'^[A-Z]{2}[0-9]{1,2}[A-Z]{0,3}[0-9]{4}$'
)

CHAR_CONFUSIONS = {
    'O': '0', 'Q': '0', 'D': '0',
    'I': '1', 'L': '1',
    'Z': '2',
    'B': '8',
    'S': '5',
}

def correct_plate_characters(text: str) -> str:
    cleaned = re.sub(r'[^A-Z0-9]', '', text.upper())
    if len(cleaned) < 4:
        return cleaned
    
    # First 2 chars MUST be state letters (e.g., MH, DL, KA)
    prefix = list(cleaned[:2])
    for i in range(2):
        if prefix[i] == '0': prefix[i] = 'O'
        elif prefix[i] == '1': prefix[i] = 'I'
        elif prefix[i] == '8': prefix[i] = 'B'
        
    # Last 4 chars MUST be registration digits (e.g., 1234)
    suffix = list(cleaned[-4:])
    for i in range(4):
        if suffix[i] in CHAR_CONFUSIONS:
            suffix[i] = CHAR_CONFUSIONS[suffix[i]]
            
    middle = cleaned[2:-4]
    return "".join(prefix) + middle + "".join(suffix)

public class RedisRateLimiterFilter extends OncePerRequestFilter {
    private final StringRedisTemplate stringRedisTemplate;
    private final boolean enabled;
    private final long requestsPerMinute; // Default: 300 req/min

    @Override
    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain filterChain)
            throws ServletException, IOException {

        if (!enabled || !isRateLimitedPath(request.getRequestURI())) {
            filterChain.doFilter(request, response);
            return;
        }

        String clientIp = resolveClientIp(request);
        long currentMinute = Instant.now().getEpochSecond() / 60;
        String key = "ratelimit:" + clientIp + ":" + currentMinute;

        try {
            Long count = stringRedisTemplate.opsForValue().increment(key);
            if (count != null && count == 1) {
                stringRedisTemplate.expire(key, 65, TimeUnit.SECONDS);
            }

            long currentCount = count != null ? count : 1;
            response.setHeader("X-RateLimit-Limit", String.valueOf(requestsPerMinute));
            response.setHeader("X-RateLimit-Remaining", String.valueOf(Math.max(0, requestsPerMinute - currentCount)));

            if (currentCount > requestsPerMinute) {
                response.setStatus(HttpStatus.TOO_MANY_REQUESTS.value()); // HTTP 429
                response.setContentType(MediaType.APPLICATION_JSON_VALUE);
                response.setHeader("Retry-After", "60");
                response.getWriter().write(String.format(
                    "{\"error\":\"Too Many Requests\",\"message\":\"Rate limit exceeded (%d req/min).\",\"retryAfterSeconds\":60}",
                    requestsPerMinute
                ));
                return;
            }
        } catch (Exception e) {
            // Fail-open: Redis down must not block legitimate user traffic
            log.debug("Redis rate limiter unavailable, falling through: {}", e.getMessage());
        }

        filterChain.doFilter(request, response);
    }
}
Critical Resiliency Design: Fail-Open Strategy

Notice the catch (Exception e) block (Lines 75–78). If the Redis server crashes or network partitions occur, the rate limiter logs a debug warning and calls filterChain.doFilter(request, response). In production high-availability systems, it is strictly preferable to temporarily serve traffic without rate limiting than to hard-fail 100% of user traffic because of a cache hiccup.

The 5-Factor Transition Plausibility Scoring Model

A naive ANPR tracking system merely connects detections in chronological order. If camera 1 reads MH12AB1234 at 18:00, and camera 10 (25 km away) misreads a bus plate as MH12AB1234 at 18:01, a naive system displays the vehicle traveling at $1500\text{ km/h}$. TrajectoryScoringService prevents this by computing a multi-criteria plausibility score:

$$\text{Score} = 0.30 S_{\text{plate}} + 0.25 S_{\text{kinematic}} + 0.15 S_{\text{geographic}} + 0.15 S_{\text{direction}} + 0.15 S_{\text{appearance}}$$

Code Implementation & Physical Speed Caps

public TransitionScore score(
        Camera fromCamera, Instant fromTime, Double fromPlateConfidence,
        Camera toCamera, Instant toTime, Double toPlateConfidence) {

    CameraGraph.Edge edge = cameraGraph.edgeBetween(fromCamera, toCamera);
    double elapsedMinutes = Math.max(0.001, Duration.between(fromTime, toTime).toSeconds() / 60.0);
    double impliedSpeedKmh = edge.distanceKm() / (elapsedMinutes / 60.0);

    double plateScore = averageOrDefault(fromPlateConfidence, toPlateConfidence, 0.5);
    double kinematicScore = kinematicPlausibility(impliedSpeedKmh);
    double geographicScore = hopPlausibility(edge.distanceKm());
    double directionScore = directionAlignment(toCamera, edge.bearingDegrees());
    double appearanceScore = 0.6; // neutral placeholder until Re-ID vectors are persisted

    boolean implausible = impliedSpeedKmh > 150.0; // 150 km/h urban physical cap

    double confidence = 0.30 * plateScore + 0.25 * kinematicScore + 0.15 * geographicScore
                      + 0.15 * directionScore + 0.15 * appearanceScore;

    String note = null;
    if (implausible) {
        confidence = Math.min(confidence, 0.15); // Hard penalty cap
        note = String.format(
            "Implied speed %.0f km/h between %s and %s exceeds physical plausibility - possible OCR misread or cloned plate.",
            impliedSpeedKmh, fromCamera.getId(), toCamera.getId());
    }

    return new TransitionScore(edge.distanceKm(), elapsedMinutes, impliedSpeedKmh,
            plateScore, kinematicScore, geographicScore, directionScore, appearanceScore,
            clamp01(confidence), implausible, note);
}

Algorithm: groupIntoVisits()

When a vehicle passes a 30 FPS camera, the detector logs 15 to 45 individual detection rows over 1 to 2 seconds. Plotting every individual detection would produce 45 redundant map points at the exact same coordinates. groupIntoVisits() collapses consecutive detections from the same camera into a single discrete CameraVisit:

private List groupIntoVisits(List detections) {
    List visits = new ArrayList<>();
    int i = 0;
    while (i < detections.size()) {
        Camera camera = detections.get(i).getCamera();
        int j = i;
        List group = new ArrayList<>();
        while (j < detections.size() && detections.get(j).getCamera().getId().equals(camera.getId())) {
            group.add(detections.get(j));
            j++;
        }

        Instant firstSeen = group.get(0).getTimestamp();
        Instant lastSeen = group.get(group.size() - 1).getTimestamp();
        
        // Select maximum plate confidence achieved across the visit
        Double bestPlateConfidence = group.stream()
                .map(VehicleDetection::getPlateConfidence)
                .filter(Objects::nonNull)
                .max(Comparator.naturalOrder())
                .orElse(null);

        // Pick snapshot frame corresponding to highest OCR confidence
        String bestImagePath = group.stream()
                .filter(d -> d.getPlateConfidence() != null)
                .max(Comparator.comparingDouble(VehicleDetection::getPlateConfidence))
                .map(VehicleDetection::getImagePath)
                .orElse(group.get(0).getImagePath());

        visits.add(new CameraVisit(camera, firstSeen, lastSeen, bestPlateConfidence,
                bestDetectionConfidence, bestImagePath, group.size()));
        i = j;
    }
    return visits;
}

Real PostGIS SQL Execution

Under the postgres profile, SpatialCameraService executes a genuine PostGIS spatial query:

SELECT id, name, latitude, longitude, direction, status
FROM cameras
WHERE ST_DWithin(location, ST_SetSRID(ST_MakePoint(?, ?), 4326)::geography, ?)
ORDER BY location <-> ST_SetSRID(ST_MakePoint(?, ?), 4326)::geography;

Detailed Query Breakdown

  • ST_MakePoint(lon, lat): Creates a 2D geometric point in WGS 84 coordinate space. Note the crucial GIS convention: Longitude ($X$) must precede Latitude ($Y$).
  • ST_SetSRID(..., 4326): Assigns Spatial Reference ID 4326 (standard GPS coordinates).
  • ::geography: Casts geometry to the spherical geography type. This enables distance measurements in true SI meters over the curvature of the Earth rather than planar degrees.
  • ST_DWithin(location, point, radiusMeters): Performs index-assisted bounding-box filtering using the table's GiST spatial index.
  • ORDER BY location <-> point: Utilizes PostGIS's K-Nearest Neighbor (KNN) distance operator, traversing the GiST R-Tree to return nearest cameras first with $O(\log N)$ performance.

2. Mathematical Formulas & Algorithms Used

A. Great-Circle Haversine Distance (GeoUtils.java)

Calculates the spherical surface distance between two junction cameras $(\phi_1, \lambda_1)$ and $(\phi_2, \lambda_2)$ with Earth radius $R = 6371\text{ km}$:

$$a = \sin^2\left(\frac{\Delta\phi}{2}\right) + \cos(\phi_1)\cos(\phi_2)\sin^2\left(\frac{\Delta\lambda}{2}\right)$$ $$d = 2R \cdot \text{atan2}(\sqrt{a}, \sqrt{1 - a})$$

B. Forward Azimuth / Compass Bearing (GeoUtils.java)

Computes the initial heading $\theta \in [0^\circ, 360^\circ)$ from the origin camera to destination camera:

$$y = \sin(\Delta\lambda)\cos(\phi_2)$$ $$x = \cos(\phi_1)\sin(\phi_2) - \sin(\phi_1)\cos(\phi_2)\cos(\Delta\lambda)$$ $$\theta = (\text{atan2}(y, x) \cdot 180 / \pi + 360) \pmod{360}$$

C. Levenshtein Edit Distance (identity_scorer.py)

Dynamic programming algorithm computing the minimum single-character edits (insertions, deletions, substitutions) required to transform plate string $s_1$ into $s_2$. Normalized string similarity is given by:

$$\text{Similarity}(s_1, s_2) = 1.0 - \frac{\text{Levenshtein}(s_1, s_2)}{\max(|s_1|, |s_2|)}$$

public class GeoUtils {
    private static final double EARTH_RADIUS_KM = 6371.0;

    public static double haversineDistanceKm(double lat1, double lon1, double lat2, double lon2) {
        double dLat = Math.toRadians(lat2 - lat1);
        double dLon = Math.toRadians(lon2 - lon1);
        double rLat1 = Math.toRadians(lat1);
        double rLat2 = Math.toRadians(lat2);

        double a = Math.sin(dLat / 2.0) * Math.sin(dLat / 2.0)
                + Math.cos(rLat1) * Math.cos(rLat2)
                * Math.sin(dLon / 2.0) * Math.sin(dLon / 2.0);

        double c = 2.0 * Math.atan2(Math.sqrt(a), Math.sqrt(1.0 - a));
        return EARTH_RADIUS_KM * c;
    }
}

SIH Hackathon Judges Defense & Technical Q&A

Q1: Why did you use Python for AI and Spring Boot for the backend instead of building everything in one language?
Defense: The computer vision ecosystem (PyTorch, Ultralytics YOLOv8, ByteTrack, EasyOCR) is fundamentally Python-first. Java deep learning bindings (such as Deep Java Library or ONNX Runtime Java) lack native ByteTrack implementations, pre-trained OCR confusion models, and flexible image dehazing pipelines. Conversely, Python web servers (Django, Flask, FastAPI) rely on the Global Interpreter Lock (GIL) and lack enterprise-grade high-concurrency thread pooling, connection pooling, and mature spatial ORM frameworks. Spring Boot serves as our hardened system of record, executing transaction isolation, Redis caching, PostGIS spatial queries, and WebSockets, while the Python service runs purely as an internal tensor inference engine.
Q2: How does your system handle vehicles with unreadable, damaged, or mud-obscured license plates?
Defense: The platform does not depend solely on license plates. Our 6-factor Identity Scoring engine (identity_scorer.py) fuses plate text (40%), ResNet50 visual appearance embeddings (30%), HSV color space profiles (12%), vehicle classifications (10%), temporal windows (5%), and camera spatial feasibility (3%). If a plate is unreadable, the system dynamically redistributes the 40% plate weight across the ResNet50 Re-ID and color features: $$w_{\text{reid}}' = w_{\text{reid}} + 0.6 \cdot w_{\text{plate}} = 0.30 + 0.24 = 0.54$$ This allows vehicle correlation across junctions based on visual make, model, shape, and color with over 80% accuracy even when plates are completely obscured.
Q3: How do you detect and alert on cloned or duplicate license plates?
Defense: Our JourneyReconstructor and TrajectoryScoringService monitor two distinct physical anomalies:
  1. Concurrent Presence (Cloned Plate): If the same normalized plate number is observed on two distinct cameras (e.g. CAM-01 and CAM-08) at the exact same timestamp ($\Delta t \le 10\text{s}$), the system immediately triggers a CRITICAL security alarm for cloned plate duplication.
  2. Impala Speed Violation: If the implied transit speed between two consecutive camera sightings exceeds physical urban plausibility ($v = d / \Delta t > 150\text{ km/h}$), the trajectory confidence is heavily penalized ($\le 0.15$) and a security alert is issued.
Q4: Why did you choose MapLibre GL JS instead of Mapbox GL JS?
Defense: Mapbox GL JS switched from an open-source license to a proprietary commercial license requiring a paid API key and credit card registration. MapLibre GL JS is the official open-source community fork maintained by the Linux Foundation. It provides the identical WebGL hardware-accelerated rendering performance, GeoJSON layer support, and 60 FPS animations without requiring external API keys or incurring commercial licensing costs.
